# PartyScreen

Discord-style screen sharing for friends. The host clicks **Share**, gets a short code, and anyone who types that code watches the screen live, with audio, from the desktop app or straight from the browser.

Video goes **peer to peer over WebRTC**. The server only handles signaling (SDP/ICE exchange), and it runs on Cloudflare Workers, so nobody has to keep a machine on or open ports.

## Features

- **Room by code:** share a screen or a single window and send the code to your friends.
- **Watch anywhere:** desktop app (macOS and Windows) or any browser, with no install.
- **Video and audio:** H.264 video and Opus audio, plus in-room chat and nicknames.
- **Per-app mute:** choose apps whose sound viewers shouldn't hear ("Mute from").
- **Hardware encoding on Windows:** NVIDIA NVENC, AMD AMF, Intel Quick Sync or Media Foundation through FFmpeg, falling back to OpenH264 on the CPU.
- **Low latency:** capture and encoding run on separate threads, and the encoder always takes the newest frame. Stale frames are dropped instead of queued.
- **Smooth over lossy networks:** keyframe requests (PLI) are rate-limited, bitrate adapts to the packet loss reported in RTCP Receiver Reports, and mDNS allows direct connections on the same LAN.
- **Works behind strict NATs:** optional TURN relay with short-lived credentials generated by the Worker.

## Architecture

```
 Host (desktop app)                         Viewer (app or browser)
 ┌──────────────────────┐                   ┌──────────────────────┐
 │ capture → encode     │ ── WebRTC (P2P) ─▶│ decode → render      │
 │ H.264 / Opus         │   or via TURN     │                      │
 └──────────┬───────────┘                   └──────────┬───────────┘
            │            signaling (WebSocket)         │
            └──────────▶  Cloudflare Worker  ◀─────────┘
                          + Durable Object (one per room)
```

The host opens one WebRTC connection per viewer (star topology), so the host's upload speed limits how many people can watch smoothly.

## Tech stack

| Part | Stack |
|---|---|
| Desktop app (`app/`) | Tauri v2, Rust, Leptos UI + Tailwind CSS |
| Capture | ScreenCaptureKit (macOS), Windows capture APIs, per-process audio capture on Windows |
| Media | webrtc-rs, OpenH264, FFmpeg hardware encoders, Opus |
| Browser viewer (`src/`) | Vue 3, Vue Router, Vite |
| Signaling (`worker/`) | Cloudflare Workers + Durable Objects |
| TURN (optional) | coturn with `use-auth-secret` (time-limited HMAC credentials) |

## Repository layout

```
app/          Desktop app (Tauri). UI in app/src (Leptos), native side in app/src-tauri
src/          Browser viewer (Vue 3), also served by the Worker
worker/       Signaling server on Cloudflare Workers + Durable Objects
server/       Original Node.js signaling server (same protocol, handy for local dev)
tela-host/    Earlier native prototype (egui), kept for reference
```

## Running locally

**Requirements:** Node.js 20+, Rust (stable), the [Tauri v2 prerequisites](https://v2.tauri.app/start/prerequisites/), and `trunk` (`cargo install trunk`).

```bash
# Browser viewer + local Node signaling server (Vite on :5173, signaling on :3001)
npm install
npm run dev

# Desktop app
cd app
npm install
cargo tauri dev
```

To work only on the desktop UI, run `npm run dev` inside `app/`. It serves the interface on `localhost:1420` with a mocked backend (`app/public/dev-mock.js`).

## Deploying the signaling server

```bash
npm run build            # builds the browser viewer into dist/
cd worker
npx wrangler deploy
```

### TURN (optional)

STUN alone can't get through symmetric NATs or corporate firewalls. To relay traffic through your own coturn server, set these secrets on the Worker. **They are never stored in the repo:**

```bash
npx wrangler secret put TURN_HOST     # your TURN server hostname
npx wrangler secret put TURN_SECRET   # same value as coturn's static-auth-secret
```

The Worker hands each client a TURN username and password that expire after 24 hours, so the shared secret never leaves the server. Cloudflare's managed TURN is also supported through the `TURN_KEY_ID` and `TURN_KEY_API_TOKEN` secrets. If no TURN secret is set, the app falls back to STUN only.

## Building installers

```bash
# macOS
cd app && cargo tauri build

# Windows installer, cross-compiled from macOS
cargo tauri build --target x86_64-pc-windows-gnu --bundles nsis
```

The Windows build bundles an LGPL FFmpeg binary for hardware encoding. It isn't committed; `app/release.sh` downloads it into `app/src-tauri/windows-libs/` when it's missing.

## Notes

- `getDisplayMedia` (screen sharing from the browser) requires HTTPS or `localhost`.
- Mobile browsers can watch, but sharing a screen from a browser only works on desktop.
